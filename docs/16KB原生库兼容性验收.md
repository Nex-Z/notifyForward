# 1.1.6 原生库 16 KB 兼容性验收

日期：2026-11-03，Asia/Hong_Kong。

## 修复

- MMKV 从 1.3.9 升级到 1.3.14 LTS，沿用原有存储格式、MMKV ID 和多进程模式。旧版 arm64 的 ELF LOAD 对齐为 0x1000，升级后为 0x4000。
- ONNX Runtime 从 1.22.0 升级到 1.31.1。最终版本未改动模型、分类头、个人标注或通知规则。
- 版本号 1.1.6 / versionCode 8，使用覆盖安装保留现有数据。

版本依据：[MMKV 1.3.14 的官方 16 KB 支持说明](https://github.com/Tencent/MMKV/releases/tag/v1.3.14)、[ONNX Runtime 1.31.1 官方发布](https://github.com/microsoft/onnxruntime/releases/tag/v1.31.1)。校验方式参考 [Android 官方文档](https://developer.android.com/guide/practices/page-sizes)。

## 验证结果

- APK 构建通过；`scripts/check-native-alignment.py` 检查全部六个 64 位原生库的 ELF LOAD 对齐、文件偏移和虚拟地址一致性，以及 APK 中未压缩条目的 16 KB 边界，全部通过。
- SDK `zipalign -c -P 16 -v 4` 输出 `Verification successful`。
- 实际设备冷启动返回 `LaunchState: COLD`、`Status: ok`，界面没有「Android 应用兼容性」提示；包管理器报告 `versionName=1.1.6`、`pageSizeCompat=0`。没有通过关闭系统提示来规避检查。
- 使用已有语义模型评测的只读模式运行 48 个样例 × 2 种模式，共 96 次推理，输出 `BENCHMARK_COMPLETE`，没有进程崩溃。这验证运行兼容性，不代表分类质量达标。
- 21:40:36 的外部测试通知成功入库，服务进程也完成语义判断；监听和前台保活服务均正常。原有一条已启用规则保留。
- 测试包已卸载，主应用保留。

测试期间候选 ONNX Runtime 1.23.2 曾在设备上触发 SIGILL，故未作为最终版本；改用 1.31.1 后上述推理检查通过。

## 重复检查

```powershell
py scripts/check-native-alignment.py app/build/outputs/apk/debug/app-debug.apk
& D:\Android\sdk\build-tools\37.0.0\zipalign.exe -c -P 16 -v 4 app/build/outputs/apk/debug/app-debug.apk
```

当前连接设备的 `getconf PAGE_SIZE` 为 4096。已完成静态对齐、系统安装检查及当前设备运行验证，尚未在真正使用 16384 内存页的设备或模拟器上运行；不据此宣称完成该环境的全部兼容性验证。
