# 语义观察与学习备份

## 当前行为

设置里的「AI 语义判断（观察模式）」开启后，新通知进入独立、最多等待 16 条的推理队列。通知详情显示正常、疑似骚扰、不确定或跳过/失败原因。AI 不再消除通知或触发静音，也不修改已有转发规则；显式规则仍按设置执行；自动智能静音已移除。总开关关闭时不运行新判断。

模型是内置的 BGE-small-zh-v1.5 量化 ONNX（约 24 MB），不是生成式聊天模型。通过 CLS 池化生成归一化 512 维向量。输入最多 128 个 token，长通知只取前段。模型文件、词表版本及 SHA-256 记录在 `app/src/main/assets/semantic/provenance.json`，原始许可随包附带。运行时不下载模型、不上传通知。

1.1.4 起使用固定语义编码器 + 轻量 Logistic 分类头 + 按应用/分身隔离的个人标注。分类头由 80 条明确标为构造数据的样例训练，512 维向量对应 512 个权重和一个偏置，不微调编码器。个人完全相同标注优先；近似样本须有足够相似度和类间差距才覆盖通用分类。分值不是校准概率，聊天推广倾向缺少个人证据时保留不确定。每类最多参考本应用最近 32 条个人样本；所有标注可备份。重复标注不累加，改标替换，支持撤销。详见 datasets/evaluation/v2/README.md 的固定测试集对比与局限。

预测是当时模型和样本的快照。更正标签影响后续判断，既有预测保留原结果，便于评估误判。无历史标注时仍可以使用预训练语义编码器和内置分类头。

## 备份与恢复

设置 → 管理学习数据 → 备份到文件 / 从备份恢复。备份使用系统文件选择器，建议放下载目录、外置存储或自行选定的云盘位置。

备份包含应用包名、是否分身、标题、正文、最终标签和更新时间，不包含 Bark 密钥或转发规则。文件是明文，应按通知内容的敏感程度保管。普通卸载会删除应用私有数据，但保存在应用外部的备份可用于重装恢复。

恢复采用合并：本机已有标注优先，同样备份多次导入不会重复学习。完整校验格式、版本、标签及长度后在 SQLite 事务中写入，校验或写入失败不部分更新。上限为 16 MB、10,000 个样本；清空学习数据会同时清除历史列表的标注，但不会删除已生成的预测快照。

旧版升级时，从仍保留的通知历史迁移最终标注；旧词频聚合模型无法逆推出已删除的通知正文，因此无法恢复这部分历史训练样本。迁移只执行一次，清空后不会再次从旧数据复活。

## 资源和可靠性边界

- 推理在独立单线程队列，ONNX 算子最多使用 2 个计算线程，不阻塞通知转发线程。
- 通知过多时跳过语义判断，记录原因；不丢弃或暂停转发。
- 连续空闲约 2 分钟释放模型会话和向量缓存，后续通知重新加载。
- 推理失败显示暂不可用，后续通知可重试；进程退出时尚未处理的任务不持久化补算，详情提示这一点。
- 保活只能作用于本应用，不能让微信恢复尚未收到的消息。
- 首版仅观察；不提供准确率承诺。需用独立、去重的真实通知测试集评估误拦风险、识别率、真机延迟与耗电。

## 验证

`gradlew.bat :app:assembleDebug :app:assembleDebugAndroidTest`

专用 Android 模拟器安装两个 APK，授权通知访问后运行：

`adb shell am instrument -w com.notifyforward.app.test/com.notifyforward.app.ForwardingAcceptance`

验收包括重复/更正/撤销、主副本隔离、备份往返、冲突与重复恢复、异常备份原子性、清理历史不删除学习、旧标注迁移、真实 ONNX 推理、跨进程标注可见性、AI 不消除通知，以及原有 Webhook/Bark 回归。

`tokenizer-golden.json` 由固定版本的上游 tokenizer.json 经 Hugging Face tokenizers 独立生成，向量由桌面 ONNX Runtime 生成；Android 验证 token 完全一致、向量余弦相似度 > 0.999。它验证接入正确性，不代表通知分类准确率。
