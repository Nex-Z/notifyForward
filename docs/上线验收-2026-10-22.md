## 本次修复

1. 正则规则先判断独立 regex 字段，避免空关键词使规则失效或错误匹配全部应用通知。
2. Bark 成功必须同时满足 HTTP 2xx 与业务 code=200，HTML、空响应和业务拒绝不再误报成功；禁用自动重定向，避免 POST 转成 GET 后误报。
3. Webhook 模板只展开一次，保留正文中的 `{message}` 等字面文本。
4. 仅转发的规则仍保留命中规则与来源；转发失败记录到数据库，并在通知列表、详情中显示。
5. 数据库版本 3 → 4 增加 `forward_error` 列；原有记录保留。
6. Android 7–9 不调用 API 29 的 `StatusBarNotification.uid`，未知 uid 记为 -1。
7. 应用自身通知显式检查 Android 13+ 通知权限，并处理权限被撤回的情况。
8. 重新打开已授权应用时请求重新绑定通知监听。

## 正式使用前的边界

- 当前没有持久化待发送队列、失败自动重试或人工补发入口。网络断开、服务进程中途终止时不能保证消息补送；失败会明确显示，但不等于可靠送达。
- 通知更新可能触发重复转发，尚无按通知 key/内容去重策略。
- 目前只有模拟器后台短时验收，未做目标 Android 手机锁屏、长时间待机、电池限制、重启及厂商 ROM 的持续测试。
- 正式分发需要固定的发布签名密钥与签名配置。不要将 debug 包称为正式上线包。
- 接收端应区分“Bark 服务器接受”与“iPhone 显示”。加密模式需两端采用一致算法及密钥；本次公网测试为明文，AES 验证在本地接收端完成。
- Android 15+ 可能隐藏含验证码的通知正文，这是系统对第三方监听器的限制，不能承诺所有通知都能读取完整内容。

参考：[Android 通知敏感内容限制](https://developer.android.com/about/versions/15/behavior-changes-all)、[Bark 官方加密协议](https://github.com/Finb/Bark/blob/master/docs/en-us/encryption.md)。

## 重复验证

仅在专用测试模拟器上运行；先为通知哨兵授予通知使用权。测试会临时修改转发设置，结束时恢复，不建议在日常主力机运行。

```powershell
.\gradlew.bat assembleDebug assembleDebugAndroidTest lintDebug assembleRelease
adb install -r app/build/outputs/apk/debug/app-debug.apk
adb install -r app/build/outputs/apk/androidTest/debug/app-debug-androidTest.apk
adb shell am instrument -w com.notifyforward.app.test/com.notifyforward.app.ForwardingAcceptance
```

未提供 `realBarkUrl` 时只运行 12 项本地测试，不联系任何真实收件人。公网测试通过 Instrumentation 参数 `realBarkUrl` 临时传入测试地址，不要把该参数的值提交到 Git。该自定义 runner 用最终 `PASS` / `FAIL` 文本报告结果，调用方必须检查该文本，不能仅凭 adb 进程退出码判断成功。
