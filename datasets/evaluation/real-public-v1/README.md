# 公开真实微信通知核查与行为测试

日期：2026-10-23。结论：找到 1 条真实消息衍生样本并运行 Android 生产推理代码，但不足以完成好友、群聊、公众号三类真实效果评测。没有新的可信精准率、召回率或 F1。

## 实际测试

来源：[SmsForwarder issue 612](https://github.com/pppscn/SmsForwarder/issues/612)，用户提交的 2025-05-21 转发故障日志。日志包含微信包名、消息正文和团队标题。根据团队标题及 @ 提及推断为群聊，不是通知系统提供的已确认会话类型。

输入：标题 `[群名]`，正文 `[成员]: @[成员] 私发你？？`。人名、提及对象和群名已替换；标题从转发日志 simInfo 重建，未取得原始 android.title。故这是脱敏后的真实消息衍生样本，不是逐字原始 Android 通知。

当前模型输出：正常，骚扰倾向分值 0.31（不是概率）。没有用户参考标签，因此不计“答对”，也不计算精准率、召回率。脱敏可能改变分值；此结果不能外推到原始消息或所有群聊。

通过 Android 模拟器调用生产 SemanticEngine，输出见 android-raw.txt 和 predictions.jsonl。模型、分类头、阈值未调整，样本未用于训练或导入个人反馈。两个运行模式重复使用同一条消息，且都没有个人支持样本，不是两条真实数据。旧 runner 的 personal16 名称不代表本次有 16 条反馈；expected=0 在此仅为无标签占位。

## 用户偏好与后续真实评测

用户要求给出选择，不统一决定好友、群聊、公众号的处理偏好。拟定每类独立选项：保留全部、按内容判断、仅指定会话参与判断。这里记录需求，不表示已实现新的设置页。来源类型无法确认的消息应单列“未知来源”，不能凭包名或名称强行归类。

参考标签应拆成内容类型（聊天/事务/营销等）与接收偏好（想接收/不想接收/待确认）。群聊营销可能是用户主动加入的优惠群，好友也可能转发营销，两者不能直接等同骚扰。

有真实手机导出后，先人工确认场景和偏好，再按会话/时间分离学习集与测试集；重复推送、相同模板不得同时进入两边。分别报告三类的样本数、误判数、未知率以及有足够标签后的精准率/召回率。只观察，不自动拦截。
