# 通知分类头优化与固定测试集对比（1.1.4）

## 实现与结论

保留现有 BGE-small-zh-v1.5 int8 编码器，替换平均近邻相似度分类法，新增在固定编码器向量上训练的二分类 Logistic 头。不是完整 SetFit：没有微调句向量编码器，只训练 512 个权重和 1 个偏置。无需新增大模型或网络推理。

本应用的完全相同标注仍优先；近似个人样本须达到相似度 0.80、两类差值 0.12 才覆盖分类头。个人标注严格按包名及分身隔离。微信等聊天来源在没有足够相近个人骚扰证据时，不凭通用推广倾向直接判为骚扰。AI 始终只观察。

## 数据与避免混用

- training.txt：80 条新编构造样例（40 正常、40 骚扰），仅它参与训练。
- 原 48 条 diagnostic-v1：已看过的开发诊断集，不能再称为独立测试集，没有加入训练。
- holdout.json：40 条新编构造样例（20 正常、20 骚扰），在训练前冻结并保存哈希，旧版和新版在安卓端使用同一份输入。未按这份测试的结果再调参数或改参考答案。
- support：沿用旧诊断集的 16 条独立参考标注，各应用正常/骚扰各 1 条。未把测试样例当作个人标注回灌。
- 所有数据仍由同一个了解实现的代理编写，不是盲测、真实数据或独立第三方评测；新样例仍可能有措辞和场景偏差。模拟类别使用 eval.* 包名，微信使用其包名以测试聊天保护。
- 测试参考 label 不传入决策，输入 sample.label 固定 0。测试与训练/参考无完全相同的标题+正文，但未声称语义无重叠。

## 同一测试集上的安卓实测

骚扰为正类；所有不确定的真实骚扰都计为漏检。误报指正常通知被判为骚扰。

| 指标 | 旧版零标注 | 新版零标注 | 旧版 +16 标注 | 新版 +16 标注 |
|---|---:|---:|---:|---:|
| 骚扰精准率 | 100%（3/3） | 94.1%（16/17） | 100%（7/7） | 94.1%（16/17） |
| 骚扰召回率 | 15%（3/20） | 80%（16/20） | 35%（7/20） | 80%（16/20） |
| 骚扰 F1 | 26.1% | 86.5% | 51.9% | 86.5% |
| 正常召回率 | 0% | 90%（18/20） | 5% | 90%（18/20） |
| 正常误报 | 0/20 | 1/20 | 0/20 | 1/20 |
| 不确定 | 37/40 | 5/40 | 32/40 | 5/40 |
| 明确判断覆盖率 | 7.5% | 87.5% | 20% | 87.5% |

本次少量个人标注没有进一步改变新版结果，不能声称此次实验证明了额外个性化收益。分类头输出 sigmoid 分值未校准，界面仍明确不是概率。新版 34/40 的参考标签得到正确分类，1 条错误、5 条不确定；不能只报告已判断子集的高分。

## 未掩盖的失败

- 正常 H016：主动预约摄影课的开播提醒，被误判为推广。需要更多订阅意图和课程提醒数据，不能依赖“直播/课程”词汇。
- 正常 H018：家人提醒不要点中奖短信，判断不确定。否定语境仍有限。
- 骚扰 H028/H029：聊天场景的陌生推销/活动群，因保护策略保留为不确定。通知文本不足以可靠证明发送人身份。
- 骚扰 H033/H034：培训促销、猎奇新闻推荐处于不确定区间。

## 模型方案选择

[SetFit 官方文档](https://huggingface.co/docs/setfit/index)介绍了少样本句向量微调加分类头路线；本版只落地轻量分类头，不把它标为 SetFit 微调模型。拿到足够真实标注后，可以评估完整 SetFit 或其他分类微调。

[BGE 官方模型卡](https://huggingface.co/BAAI/bge-small-zh-v1.5)说明相似度门槛应结合具体数据分布选择，不能把一个固定值当通用分类器。

[Qwen3-Embedding-0.6B 官方模型卡](https://huggingface.co/Qwen/Qwen3-Embedding-0.6B)提供 0.6B 参数级的新编码器。它仍需分类方法和目标数据；本次没有下载或实测它，不能声称它在通知任务中优于当前方案。考虑手机常驻资源，本次先保留现有小编码器并改善任务分类层。

## 复现与验收

训练：从仓库根目录执行 `.model-cache/verify-env/Scripts/python.exe datasets/evaluation/v2/train_head.py`。需要 numpy、onnxruntime、tokenizers，以及 `.model-cache/tokenizer.json`。脚本不读取 holdout。阈值 0.35/0.65、L2=0.001、2500 次梯度迭代固定。模型、分词器和训练数据哈希见 run-manifest.json。

构建、安装 app 与测试 APK 后：

```powershell
adb shell am instrument -w -e benchmark true -e dataset holdout-v2.json com.notifyforward.app.test/com.notifyforward.app.ForwardingAcceptance
```

before/after 原始输出和 predictions JSONL 均保留，必须包含 BENCHMARK_COMPLETE、每轮 40 条。旧分类代码保留在 baseline-engine.kt.txt（不参与编译），防止随着生产代码修改失去审计依据。

常规安卓验收 29 项通过；真实模型推理、分词/向量与 Python 参考一致、标注纠正、备份、跨应用隔离、通话保护与转发链路均未回归。没有真实手机性能或真实通知准确率验收。分类器仍仅观察，默认不自动拦截。
