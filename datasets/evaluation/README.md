# 当前语义分类器诊断评测（2026-10-23）

结论：当前配置大量弃权，尚不能作为成熟的正常/骚扰分类器。继续观察模式，不建议据此开启自动拦截。本次测量的是 BGE 编码器 + 内置样本 + 当前阈值/应用隔离策略的整体效果，不是 BGE 模型本身的通用能力。

## 数据与实验约束

- 48 条人工构造的诊断样例：24 正常、24 骚扰，8 类应用场景各 6 条。非真实手机通知，非公开基准，样例由了解实现的编码代理编写。不能外推真实准确率。
- 另有 16 条人工构造的个人标注样例，各应用 1 正常 + 1 骚扰；不与测试样本的包名/标题/正文组合完全重复。每条推理最多使用本应用的 2 条；不是每条都使用 16 条。
- 有刻意重复的跨来源文案用于对照；这些样例不是统计独立同分布样本。没有随机真实测试集或多用户偏好评审。
- 参考标签代表一个明确的模拟偏好：保留私人/工作交流、交易、安全及已订阅提醒；拒绝主动商业推广、无订阅的推荐和欺诈消息。好友分享优惠不是自动判为骚扰。
- 除微信使用当前实现识别的包名外，其他场景使用 eval.* 测试包名；未声称真实购物/银行等应用采集。
- 测试标签不传给模型决策：judge 当前不读取输入样本的 label；个人参考样本只来自 support。未写入或读取用户手机标注库。
- 使用安卓模拟器实际调用生产 SemanticEngine.judge 和随 APK 附带的 ONNX 模型，两轮各 48 次推理。固定样例后未根据结果调整标签、阈值或模型。两轮各重新释放模型缓存。

## 指标

“骚扰”是正类；不确定计入骚扰漏检。未把弃权算正确正常。覆盖率=给出正常或骚扰判断的条数/48。以下精准率只有极小分母，不能解读为可靠的 100% 实际准确率。

| 指标 | 零个人标注 | 加入 16 条参考标注 |
|---|---:|---:|
| 骚扰精准率 TP/(TP+FP) | 100%（5/5） | 100%（11/11） |
| 骚扰召回率 TP/24 | 20.8%（5/24） | 45.8%（11/24） |
| 骚扰 F1 | 34.5% | 62.9% |
| 正常误报为骚扰 FP/24 | 0/24 | 0/24 |
| 正常召回率 | 0/24 | 0/24 |
| 明确判断覆盖率 | 10.4%（5/48） | 22.9%（11/48） |
| 不确定 | 43/48 | 37/48 |

正常类从未被预测，正常类精准率无定义，不能写成 0% 或 100%。已判断子集准确率虽然为 100%，但排除了大部分样本，不代表总体分类能力。

混淆矩阵：行=真实正常/骚扰，列=预测正常/骚扰/不确定。

- 零标注：[[0, 0, 24], [0, 5, 19]]
- 少量标注：[[0, 0, 24], [0, 11, 13]]

## 发现与后续

当前策略难以确认正常类，整体覆盖低。对照实现，可能与每类取最高三个相似度均值、0.65 最低相似度、0.08 分差以及有限的内置正常参考样本共同有关；本次没有做消融实验，不能把原因确定归于某一个阈值。仅降低门槛可能增加正常通知误报，不应在此测试集上反复调参并把分数当作泛化表现。

下一步应收集经用户纠正且脱敏的真实通知，并按时间、发送人/会话和近重复模板分组切分参考集、验证集、最终测试集；应用分别报告指标。完整保留不确定率、各类召回率和误报率。私聊分享与商业推广需要更多来源上下文，仅靠 App 包名仍不够。

## 复现

在专用安卓模拟器安装当前 debug APK 与测试 APK 后运行：

```powershell
./gradlew.bat :app:assembleDebug :app:assembleDebugAndroidTest
adb install -r app/build/outputs/apk/debug/app-debug.apk
adb install -r app/build/outputs/apk/androidTest/debug/app-debug-androidTest.apk
adb shell am instrument -w -e benchmark true com.notifyforward.app.test/com.notifyforward.app.ForwardingAcceptance
```

结果每条以 EVAL JSON 输出，最后必须有 BENCHMARK_COMPLETE。该 benchmark 分支不执行常规验收的数据库清理及网络发送操作。JSONL 保存了每条判断原因和推理耗时；模拟器耗时不能代表真实手机。
